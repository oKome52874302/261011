# MacroLog — 筋トレ・ダイエット向け食事記録アプリ

スマホのブラウザで動く、PFC（たんぱく質・脂質・炭水化物）管理に特化した食事＋筋トレ記録Webアプリです。
ビルド不要・サーバー不要。データは各自の端末のブラウザ（localStorage）に保存されます。

## 公開方法（友達とURLで共有）
1. このブランチを `main` にマージ
2. GitHub のリポジトリ → **Settings → Pages** → Source: *Deploy from a branch* / Branch: `main` / `/(root)` → Save
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
4. スマホで開いて「ホーム画面に追加」するとアプリのように使える

※ カメラ（バーコード読み取り）は HTTPS が必須なので、GitHub Pages などで公開して使ってください。
ローカルで試すときは `python3 -m http.server` で起動し `http://localhost:8000` を開きます（`file://` 直開きは不可）。

## 機能
### 食事
- 目的（減量／維持／増量）と体格から **目標kcal・PFCを自動計算**（手動上書き可）
- **カーボサイクル**：トレ日は炭水化物を増やして＋10%、休養日は−10%（筋トレを記録した日は自動でトレ日）
- 内蔵食品 **約150品**（主食・肉・魚・卵大豆・乳/プロテイン・野菜・果物・ナッツ/油・調味料・外食/惣菜・飲料・お菓子）。ひらがな検索・カテゴリ絞り込み対応
- **🏷 成分表示を撮影（APIキー不要）**：パッケージの栄養成分表示を**スマホ内のOCR**で読み取り、kcal・PFCを自動入力。画像は外部に送信せず、オフラインでも動作（初回のみOCRデータ約6MBを読み込み）
- **📋 テキスト貼り付け**：iPhoneの「テキスト認識表示」でコピーした成分表示を貼り付けると自動入力
- **📷 食事写真 → 目分量で記録（APIキー不要）**：撮った写真を画面上部に表示したまま、食品と量を選んで続けて記録。量は g のほか **✋手のひら・✊こぶし・👍親指・ご飯の小/普通/大盛り** の「手ばかり」で選べる（設定で手の大きさを補正）
- **📖 レシピから計算（APIキー不要）**：レシピの写真（スマホ内OCR）・PDF（文字入り／スキャン）・貼り付けテキストから材料を読み取り、「大さじ2」「1/2個」「1枚(300g)」などをgに換算して食品データと照合 → 全体と1人分のPFCを計算。1人分を記録 or マイ食品に保存
- **📷 食事写真AI（任意・要APIキー）**：食事写真から料理ごとの重量と栄養をClaudeが推定。成分表示の読み取りがうまくいかない時のAI読み取りにも使える
- **▥ バーコード**：JANコードを読み取り、Open Food Facts で商品を検索。見つからなければ成分表示撮影 or 手入力で登録 → 次回からそのバーコードで呼び出し
- マイ食品、最近使った食品、**食事セット**（よく食べる組み合わせを保存）、前日コピー
- たんぱく質の残りを「鶏むね肉◯g／プロテイン◯杯」に換算表示

### 歩数・ヘルスケア（iPhone）
- iPhoneの「ショートカット」アプリでヘルスケアの**歩数・距離・アクティブエネルギー**を読み出し、URL（Safari）またはクリップボード（ホーム画面アプリ）で取り込み。毎日自動化も可能
- 設定画面にショートカットの作り方を掲載。誰か1人が作って iCloud リンクを登録すると「⚡ ワンタップでショートカットを追加」になり、友達への招待リンクにも同梱される（`js/config.js` の `SHORTCUT_ICLOUD_URL` に入れると全員に表示）
- 食事画面の「🔄 同期」でショートカットを直接実行（Safariは終了後に自動で取り込み、ホーム画面アプリは戻ってから「📋 取り込む」）
- 手入力にも対応（Androidはブラウザから歩数を読む手段がないため手入力）
- 「歩数・活動カロリーを目標に反映」をオンにすると、活動レベルを最小にして実際の活動消費を目標に上乗せ（二重計上しない）
- 歩数の実績（1万歩・累計100kmなど）、週間レポートに平均歩数・合計距離

### 友達グループ（食品共有）
- バーコードで登録した商品を、**招待コードを知っている友達だけ**で共有（誰か1人が登録すれば全員がバーコードで呼び出せる）
- 「📤 LINEで招待」で招待リンクを送り、開くだけで参加。検索の「みんなの食品」にも表示
- ログイン不要。サーバーは Supabase（無料枠）を使い、行レベルセキュリティで他グループのデータは読めない

### 筋トレ
- **メニュー**：「胸の日」などのメニュー（種目・セット×回・重量）を登録し、▶開始でその日の種目と目標をセット。目標の達成状況（2/3セットなど）を表示
- **紙のメモ読み込み**：メモの写真（スマホ内OCR、APIキーがあればAI）や貼り付けテキストから、種目と重量×回数を取り込んで記録 or メニュー化。「60×10×3」「80kg 10/10/8」「10回×3セット」などに対応
- 種目×セット（重量・回数）を記録。**前回の記録を表示**し、入力欄にも前回値を自動セット
- 推定1RM（Epley式）、ボリューム、**自己ベスト更新の通知**、週ごとのトレ日数・総ボリューム

### 実績・レベル
- **実績27種**（記録・栄養・筋トレ・体重・機能）、XPとレベル、**今週のチャレンジ**（記録5日・たんぱく質4日・筋トレ3日）
- **連続記録**は7日に1回まで「おやすみ」OK（1日忘れただけでリセットされない）
- 体重の増減やカロリーの少なさではなく、**記録・たんぱく質・トレーニングという行動**を評価する設計

### 週間レポート共有
- 「📤 今週の結果を送る」で、記録日数・たんぱく質達成・平均kcal・筋トレ・自己ベスト・実績を**画像カード＋テキスト**にまとめて LINE などへ送信（今週／先週を切替）
- スマホでは共有メニューから画像付きで送信、未対応の端末は LINE のテキスト共有。アプリのURL付きなので友達もすぐ始められる

### 体重
- 推移グラフ＋7日移動平均。週あたりの変化率から、目的に応じて「速すぎ／遅すぎ」をアドバイス

## 友達グループの設定（最初の1人だけ）
1. [Supabase](https://supabase.com/) で無料アカウントを作り、**New project** を作成（リージョンは Tokyo 推奨）
2. 左メニュー **SQL Editor** → [`supabase/schema.sql`](supabase/schema.sql) の中身を貼り付けて **Run**
3. **Project Settings → API**（または *API Keys*）で **Project URL** と **anon（publishable）key** をコピー
4. アプリの 設定 → 友達グループ →「管理者向け：共有サーバー設定」に貼り付けて保存 →「新しいグループを作る」
5. 「📤 LINEで招待」で友達に招待リンクを送る（友達はリンクを開くだけで参加・設定完了）

※ URL と anon key は公開前提の値です（読み書きの制限は RLS で行う）。`js/config.js` に書けば全員のアプリに組み込めます。

## 写真AIの設定
設定 → 写真AI に各自の Claude APIキー（[Anthropic Console](https://console.anthropic.com/) で発行）を入力します。
- キーはその端末の localStorage にのみ保存され、JSON書き出しには含まれません
- ブラウザから直接 API を呼ぶ方式のため、**キーは他人と共有しない**こと、Console で**利用上限を設定**しておくことを推奨
- モデルは Opus 5.5（既定・高精度）／Sonnet 5.5／Haiku 5.5（低コスト）から選択

## 計算ロジック
- 基礎代謝：Mifflin-St Jeor式 → TDEE＝基礎代謝×活動係数
- 目標kcal：減量 TDEE×0.8／維持 ×1.0／増量 ×1.1
- たんぱく質：体重×（減量2.2／維持1.8／増量2.0）g、脂質：総kcalの25%、残りを炭水化物

## 注意
- 内蔵食品の栄養値は日本食品標準成分表（八訂）等を参考にした**概算値**です。「目安」表記の市販品・外食は差が大きいので、表示があればそちらを優先してください。
- 成分表示のOCRは撮り方（ピント・傾き・光の反射）で精度が変わるので、自動入力された数値は確認してください。
- 写真からのAI推定は誤差が大きい（±20〜30%程度）ので、参考値として使ってください。
- バーコード検索は [Open Food Facts](https://world.openfoodfacts.org/)（ODbL）のデータを利用しています。日本の商品は未登録のものも多いです。
